# QHR 加班助手

基于 C#、.NET 8 和 WPF 的 QHR 打卡统计工具。程序使用公司账号向 SSO 获取当前会话 token，再建立 QHR 会话读取打卡流水；不需要打开浏览器。启用自动登录后，密码由 Windows 凭据管理器加密保管，不会写入程序配置文件，token 始终只保存在当前进程。

## 功能

- 按每日、月度、年度汇总加班时间和预估加班费。
- 概览只允许按年份和月份选择整月数据，月历沿用“加班 3h55m”的原有格式，时长按“原始加班－延时工时抵扣”显示；加班费总数也排除延时工时。事假在此基础上按月抵扣计费，月度封顶再处理超额部分，均不覆盖原始考勤。页面提供上个月、下个月、本月快捷切换，点击日期可查看首末卡、各类抵扣、封顶无效时长、餐补和当天费用详情，填写备注并保存加班证据图片，当前月自动禁用“下个月”。
- 切换月份后自动防抖读取本地档案，无需手动点击刷新；本地已有整月数据时不联网、也不显示刷新遮罩。
- 程序启动时更新一次本月和上月，头像菜单的“刷新数据”可主动再次更新；查看其他月份只在本地整月为空时联网补取该月份，同一运行会话内每月最多自动尝试一次。空响应或部分响应不会删除既有本地数据。
- 升级到按日区分请假类型的版本时会执行一次历史请假迁移：从已完成审批详情读取实际开始/结束日期、事假/年假类型与时长并补入现有加密档案，不重抓历史打卡；完成后仍只更新本月和上月。
- 独立“分析汇总”页面默认只分析今年，也可切换为近三年、近五年和近十年，不受概览所选月份影响；月度图合并对比加班费与餐补次数，并按工作日、周末、节假日展示加班时长构成。
- 每日备注与证据图片使用 Windows DPAPI 独立加密，按“年/月/日/单图”分片保存并按需加载；每张图片限制 20 MB、每天限制 30 张，避免考勤主档案和单个数据文件无限膨胀。
- 当天详情可一键导出单日 ZIP，月历可导出整月或所选年份 ZIP；年度包按“年份/月份/日期”分层，每天固定包含加班数据和加班证据目录，同时提供年度、月度 CSV，便于报销、留档或发送。
- “加班目标”页面可同时保存多个购买目标，并随时指定当前生效目标；每次生效、结束和被其他目标替换的准确时间都会保存在本地，点击目标即可查看完整生效记录。目标可选择只计算加班费或计算加班费与餐补；消费记录会减少实际有效金额，且可修改日期、说明和金额。目标和消费使用 Windows DPAPI 加密保存。达到目标后会播放一次庆祝动画并自动归档；历史目标可修改，在当前没有目标时也可连同当时的消费恢复为当前目标。
- 默认费率：工作日 20 元/小时、周末 30 元/小时、节假日 60 元/小时，均可在界面修改。
- 支持配置月度加班费封顶金额；超额部分记录为封顶无效加班时长和少计金额。节假日加班费默认不占用封顶额度，可动态改为纳入；启用或修改规则时可选择应用到全部历史数据，或从指定日期起生效。
- 后台自动同步中国法定节假日与调休工作日，在线失败时使用本地缓存；同步及加密档案状态统一显示在概览，节假日直接在月历中用特殊颜色标记。
- 自动读取 QHR 月度考勤汇总及状态为“完成”的“请假申请”；审批详情按实际请假日期保存，事假在所在月度内统一抵扣加班，年假和无法确认类型的请假不抵扣。
- 自动读取状态为“完成”的“延时工时扣减申请”，按申请发生日期和 `AMOUNT` 分钟数优先抵扣当天加班；抵扣部分不计算加班费，也不参与餐补门槛。
- 获取后的打卡、请假/缺勤、餐补次数和班次快照会使用 Windows DPAPI 加密保存；QHR 清空历史字段或暂时不可访问时自动使用本地档案补回。
- 支持配置弹性上班窗口、工作日起算时间、餐补门槛、最小加班时长和取整粒度。
- 支持 SSO 账号密码登录，以及已有 QHR Token 的高级登录方式。QHR 或公司网络不可用时可直接离线查看本机加密保存的考勤、目标和消费记录；自动登录连接失败且存在本地记录时会自动进入离线模式，离线刷新不会请求 QHR。
- 支持通过 Windows 凭据管理器自动登录，主动退出账号时自动清除凭据。
- 支持从“计算设置”或头像菜单一键备份全部数据，使用独立密码加密为可跨电脑迁移的 `.qhrbackup` 文件；导入时会重新使用新电脑的 Windows 用户加密。考勤、设置、目标、消费、备注、证据图片和节假日缓存都会迁移，SSO 密码与会话 token 不进入备份。
- 导入备份只合并、不删除本机独有数据；发现同日期考勤、同一消费、设置、备注或证据冲突时，必须由用户明确选择“保留本机冲突项”或“使用备份冲突项”。
- 当前版本为 1.3.26。本版本理清了多目标的收入与消费归属：追溯加班费起算日只转移对应区间的加班收入，不会自动搬动其他目标的消费；每笔新消费归属于记录时的当前目标，并可在当天消费详情中明确把尚未计入的记录转入当前目标。目标进度、完成归档和历史恢复统一按“累计收入－本目标消费”的实际有效金额计算，达到目标时会先展示完整算式并由用户确认，恢复历史目标时会校验并恢复消费明细。目标实际生效区间、替换记录和旧消费档案均可平滑迁移，月度消费账本继续保留全部记录。更新提示不再暴露具体托管平台名称。发布包使用 `QHR.Overtime-v版本-win-x64-Release.zip` 命名。头像菜单的“检查更新”会读取 [QHR 在线发布页](https://github.com/JIANXINXIAOQINGMING/QHR/releases/latest)，选择版本一致的 Windows x64 ZIP，显示版本、文件名、大小和下载进度，下载后同时核对文件名版本与 `app` 内主程序真实版本，再退出程序、覆盖安装并通过根目录启动器自动重启；在线更新不可用时仍会回退检查安装根目录中的本地更新包。
- 内置 WebView2 QHR 请求诊断窗口，可从右上角头像菜单打开；支持脱敏记录请求与 JSON 响应并导出。

## 默认计算规则

- 工作日：08:30–09:30 弹性上班，统一从配置的工作日起算时间（默认 19:00）计算到末卡，不再使用“标准在岗跨度”推算下班时间。
- 周末/节假日：从首卡到末卡直接计算，不扣除午休或晚餐。
- 请假抵扣：仅状态为“完成”的事假参与所在月度的净加班计算，先抵扣低费率加班；年假和未知类型请假只显示、不抵扣。事假多于加班时，净加班显示为负数，最终“预估到手”按 0 元下限计算；“总加班费”仍保留事假抵扣前的金额。
- 延时工时抵扣：仅同步审批状态为“完成”的申请，按分钟换算成小时后先从当天原始加班中扣减；月历加班时长、加班费总数、餐补门槛和后续的事假抵扣均以扣减后的时长为基础。
- 加班费封顶：默认关闭；启用后按自然月、按日期顺序消耗额度，超过额度的金额与对应时长不计入实际加班费。默认排除法定节假日加班费，餐补始终不占额度。
- 餐补：工作日加班满 1 小时补贴 20 元；周末或节假日满 4 小时补贴 20 元。餐补金额和门槛均可配置。
- 默认最小加班时长为 0，所有完整分钟都参与计费；餐补仍分别使用工作日 1 小时、周末/节假日 4 小时门槛。
- 节假日 JSON 中只有法定节假日本身按节假日费率；连续假期内其余 `isOffDay=true` 的休息日按周末费率，`isOffDay=false` 的调休上班日按工作日费率。

这些规则都可在“计算设置”页面调整。结果依据打卡跨度计算，仅作为个人估算，不替代审批记录或工资单。

## 构建与运行

```powershell
dotnet build QHR.csproj -c Release
dotnet run --project QHR.csproj
```

需要 Windows 10/11 和 .NET 8 Desktop Runtime。访问 SSO 与 QHR 时需要能够连接公司网络。

如需直接打开诊断浏览器：

```powershell
.\QHR.Overtime.exe --capture
```

诊断浏览器需要 Microsoft Edge WebView2 Runtime（Windows 10/11 通常已预装）。

生成可直接分发的 Windows x64 自包含 ZIP（目标电脑无需安装 .NET 8）：

```powershell
.\Tools\Publish-Package.ps1
```

生成结果按项目版本命名，例如 `artifacts\QHR.Overtime-v1.3.26-win-x64-Release.zip`。创建 GitHub Release 时，标签需包含相同版本号（例如 `v1.3.26`），并将这个 ZIP 作为 Release asset 原名上传；在线更新只接受与 Release 版本一致且严格符合该命名的 Windows x64 包。解压后根目录只有原生启动器 `QHR.exe` 和 `app` 文件夹；全部 .NET/WPF 程序文件及运行库保持原始相对结构放在 `app` 内，无需另装 .NET。首次安装直接运行根目录的 `QHR.exe`。从 1.3.3 或更早版本升级到此新布局时，请先退出程序并删除旧程序目录内容，再完整解压新包；1.3.4 及以后既可从在线发布页更新，也可把新版 ZIP 放在 `QHR.exe` 同级根目录后从程序内更新。用户数据位于本机应用数据目录，不会随程序目录删除。

## 数据位置

配置、节假日缓存和加密考勤档案位于：

```text
%LOCALAPPDATA%\QHR.Overtime\
```

考勤档案和目标账本位于其中的 `secure` 目录，按 QHR 账号隔离，并通过 Windows DPAPI 绑定当前 Windows 用户，文件本身不是可读 JSON。密码与会话 token 不写入该目录；自动登录密码保存在当前 Windows 用户的凭据管理器中。节假日默认使用 [NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn) 的全年 JSON，可在设置中替换为兼容地址。

换电脑时，请先在旧电脑创建 `.qhrbackup` 全量备份并记住备份密码；在新电脑登录同一 QHR 账号后选择“导入备份”。备份使用 PBKDF2-SHA256 派生密钥、AES-256-CBC 加密并以 HMAC-SHA256 校验完整性，处理证据图片时采用流式读写，避免数据较大时一次占满内存。

脱敏后的 QHR 诊断文件保存在 `%LOCALAPPDATA%\QHR.Overtime\captures\`。
